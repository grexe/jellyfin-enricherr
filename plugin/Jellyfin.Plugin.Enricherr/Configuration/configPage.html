Preferred language searches in the item's own language first, same as any other search - which can settle for a mediocre same-language result (the search stops at the first successful download, regardless of resolution) without ever trying English, which often has a genuinely higher-quality upload available. Best quality skips the native-language search stage, going straight to English/best-available - prioritizing resolution over language match.

Organisation

Rename the movie file to match its resolved title, e.g. "Movie Name (Year).ext".
Rename a TV series' own top-level folder to match its resolved title, e.g. "Series Name (Year)", and its season subfolders to Jellyfin's own canonical "Season NN" ("Specials" for season 0) - based on Jellyfin's own resolved season number for each, not parsed from the subfolder's own name. A release-style folder name (tags, resolution, season ranges, ...) can still resolve to the right trailer via search - Jellyfin's own matching is forgiving enough for that - but the folder names themselves are what drive Jellyfin's own poster match in the collection/list view and displayed title, which the search step never touches. Episode files themselves are never renamed or moved.
Jellyfin only recognizes a local trailer file when the movie has its own dedicated folder (jellyfin/jellyfin#10077). When this is "Disabled", a movie without its own folder is skipped entirely (logged as a warning) rather than downloading a trailer Jellyfin could never show.
When a folder/file this plugin creates or writes into ends up with permission bits or a group that deny access to whichever user Jellyfin itself runs as (common when media was added by a different user/process, e.g. over SMB), match its permission bits and group to an already-working reference file next to it. Off by default, since this plugin changing filesystem permissions on its own is an intrusive default - turn on only if you actually hit permission errors. No effect on Windows.

Theme Songs

Also download a local theme song (theme.mp3) for each movie/series, looked up on ThemerrDB by TMDb id - the same community-curated database the Themerr-jellyfin plugin uses, so an item only gets a theme song here if Themerr would have offered one too. The lookup is the only thing shared with Themerr; the download itself goes through this plugin's own yt-dlp pipeline instead of Themerr's downloader. An item with no TMDb id, or no ThemerrDB entry, is silently skipped - this never touches an existing theme.mp3, whether user-provided or already downloaded by Themerr.

Network

Used by yt-dlp for authenticated/age-restricted YouTube access. No browser (Firefox, Chrome, Safari, ...) stores cookies as a plain file you can point to directly - Firefox keeps them in an SQLite database inside its profile folder, not a "cookies.txt". Export one instead: install the "Get cookies.txt LOCALLY" extension (also on the Chrome Web Store; avoid the plain "Get cookies.txt" one, it was pulled as malware), sign in to a YouTube account that's passed age verification, open youtube.com, and use the extension to export the current site's cookies as a Netscape-format cookies.txt - then upload that file here. Saved immediately on upload - not part of the Save button below.
Minimum wait before each yt-dlp request. A large library can add up to many separate requests with no pacing between them, which can trip YouTube's own rate limiting - that then blocks the whole session for up to an hour, with every remaining movie/series failing until it lifts. Lower this only if you're confident it won't happen; 0 disables the delay entirely.
If YouTube rate-limits the session anyway, wait, then retry the rest of the run exactly once instead of stopping immediately. There's no reliable way to know when the limit actually lifts - YouTube's own message only states an upper bound - so this is a single bounded retry, not a backoff loop: if the retry also gets rate-limited, the run stops for good.
How long to wait before that single retry. Defaults to a bit past YouTube's own stated "up to an hour" ceiling - retrying too early just spends the one retry hitting the same still-active limit. Disabled unless "Retry once if rate-limited" above is on.
